INCIDENT #1: OpenRouter 404 HTML Response (API Routing Regression)
--------------------------------------------------------------------------------
Symptoms & Error:
  - Running 'python src/agent/classify.py' printed hundreds of lines of raw HTML:
    '<!DOCTYPE html>...<title>Not Found | OpenRouter</title>...404: Not Found'
  - The client failed to connect to OpenRouter and dropped straight into fallback.

Root Cause:
  - 'OPENAI_BASE_URL' in 'src/config.py' and '.env' was incorrectly configured as:
    'https://openrouter.ai/nex-agi/nex-n2.5-mini:free'
  - The OpenAI SDK automatically appends '/chat/completions' to the base URL,
    causing requests to hit:
    'https://openrouter.ai/nex-agi/nex-n2.5-mini:free/chat/completions'
    This route is a frontend web page on openrouter.ai, not an API endpoint.

Fix Applied:
  1. Updated 'src/config.py' to point strictly to the v1 REST endpoint:
     OPENAI_BASE_URL = "https://openrouter.ai/api/v1"
  2. Separated the model identifier into its own environment variable:
     DEFAULT_MODEL = "nex-agi/nex-n2.5-mini:free"
  3. Added 'override=True' to 'load_dotenv(BASE_DIR / ".env", override=True)'
     so stale terminal export variables do not shadow project config.

Verification Output:
  Base URL: https://openrouter.ai/api/v1
  Model: nex-agi/nex-n2.5-mini:free
  Key loaded: True
  HTTP Status: 200 OK

INCIDENT #2: OpenAI SDK 'Choice' Attribute Schema Mismatch
--------------------------------------------------------------------------------
Symptoms & Error:
  - Terminal output:
    "LLM API call failed: 'Choice' object has no attribute 'messages'"
  - Execution fell back to mock generation.

Root Cause:
  - Inside 'src/llm_client.py' (line ~38), the code accessed:
    'response.choices[0].messages.content'
  - The official OpenAI Python SDK schema defines this object property as
    singular: '.message' (ChatCompletionMessage), not plural '.messages'.

Fix Applied:
  - Corrected line in 'src/llm_client.py':
    Old: return response.choices[0].messages.content.strip()
    New: return response.choices[0].message.content.strip()

Verification Output:
  Message object: ChatCompletionMessage(content='Hi! How can I help you', role='assistant')
  Content: Hi! How can I help you

INCIDENT #3: Silent 'NoneType' Return in LLMClient.generate()
--------------------------------------------------------------------------------
Symptoms & Error:
  - Running:
    python -c "from src.llm_client import LLMClient; print(LLMClient().generate('Respond with: OK'))"
    Returned: 'None'
  - Downstream crash in 'src/agent/classify.py':
    "AttributeError: 'NoneType' object has no attribute 'strip'"

Root Cause:
  - Inside 'src/llm_client.py', the 'return content.strip()' line inside the
    try block had been commented out or bypassed without an explicit return.
  - Python defaulted to returning 'None' from the method.

Fix Applied:
  - Explicitly restored and safeguarded the return contract in 'src/llm_client.py':
    content = response.choices[0].message.content
    if not content:
        raise ValueError("LLM returned an empty response.")
    return content.strip()
  - Added defensive check in 'classify.py' to ensure 'raw_response' is non-None
    before invoking string operations.

Verification Output:
  $ python -c "from src.llm_client import LLMClient; print('LLM Output:', LLMClient().generate('Respond with: OK'))"
  LLM Output: OK

INCIDENT #4: Indentation Bug in Keyword Baseline Classifier (Early Termination)
--------------------------------------------------------------------------------
Symptoms & Error:
  - Queries like "My payment got stucked i din't recieved it yet" and
    "My app keeps freezing after the update" unexpectedly classified as:
    Intent: 'other'
    Confidence: 0.7
    Reasoning: 'Fallback to keyword classifier.'

Root Cause:
  - In 'src/intent.py', 'classify_intent_by_keywords()' had an indentation error:
      for intent, keywords in KEYWORD_RULES.items():
          if any(key in text_lower for key in keywords):
              return intent
          return "other"   # <-- FATAL: Indented inside the loop
  - Because 'return "other"' was inside the loop body, if the message did not
    match the very first taxonomy entry ('delivery_delay'), the loop terminated
    immediately without checking 'payment_issue', 'product_defect', etc.

Fix Applied:
  - Moved 'return "other"' outside the 'for' loop scope.
  - Upgraded 'KEYWORD_RULES' with linguistic word stems ("pay", "charg", "stuck",
    "deduct", "fee") so typos and tense shifts match reliably during fallback.

Verification Output:
  $ python src/intent.py
  Text: My payment got stucked i din't recieved it yet
     -> Intent: payment_issue | Escalate: True
  Text: My app keeps freezing after the update
     -> Intent: product_defect | Escalate: False

INCIDENT #5: Markdown Code Fence (```json) JSON Parsing Failures
--------------------------------------------------------------------------------
Symptoms & Error:
  - LLM successfully generated responses, but classifier always returned:
    "Fallback to keyword classifier."
  - Standard 'json.loads()' threw 'json.decoder.JSONDecodeError'.

Root Cause:
  - Most LLMs (including 'nex-agi/nex-n2.5-mini:free') wrap structured JSON in
    Markdown formatting fences:
      ```json
      {"intent": "payment_issue", "confidence": 0.98, ...}
      ```
  - Direct 'json.loads()' fails on backticks.

Fix Applied:
  - Built an extraction layer in 'src/agent/classify.py':
    1. Strip leading and trailing whitespace.
    2. Strip '```json' or '```' markdown prefixes and suffixes.
    3. Added regex fallback matching outermost '{...}' if conversational prose
       accompanies the payload.

Verification Output:
  [DEBUG RAW RESPONSE]: '{"intent":"payment_issue","confidence":0.98,"reasoning":"The customer says their payment got stuck, indicating a payment processing issue."}'
  
  --- Result ---
  Message:    My payment got stucked i din't recieved it yet
  Intent:     payment_issue
  Confidence: 0.98
  Reasoning:  The customer says their payment got stuck, indicating a payment processing issue.

INCIDENT #6: Multi-Provider Failover & API Rate Limit Handling (HTTP 429)
--------------------------------------------------------------------------------
Symptoms & Error:
  - Running 150 benchmark test cases repeatedly triggered OpenRouter free tier limit:
    'Error code: 429 - Rate limit exceeded: free-models-per-day'
  - The OpenAI client paused in exponential backoff retries, slowing down evaluation.

Root Cause:
  - OpenAI SDK defaults to 'max_retries=2', making repeated network calls on quota exhaustion.

Fix Applied:
  1. Configured 'max_retries=0' in 'src/llm_client.py' to eliminate retry delays on quota limits.
  2. Added single-warning rate limit detection: when a 429 occurs, 'LLMClient' logs a single
     clean warning line and immediately switches to fast local fallback mode for subsequent calls.
  3. Integrated Groq API ('https://api.groq.com/openai/v1') with key resolution in 'src/config.py'
     to allow high-speed live cloud inference (500+ tokens/sec).

Verification Output:
  ⚠️ API Rate Limit hit (429). Switching to fast offline fallback mode.
  Pipeline completes 150 evaluations in sub-second speed without crashing.

INCIDENT #7: Groq Model Deprecations & Reasoning Tag (<think>) Stripping
--------------------------------------------------------------------------------
Symptoms & Error:
  - Initial Groq model IDs ('llama3-8b-8192', 'gemma2-9b-it') returned 400 decommissioned errors.
  - Reasoning models like 'qwen/qwen3.6-27b' output internal '<think>...' reasoning text that
    consumed token budgets before completing responses.

Root Cause:
  - Groq updated its active model suite, deprecating older Llama 3 legacy endpoints.
  - Open-weights reasoning models prefix final replies with '<think>' reasoning blocks.

Fix Applied:
  1. Configured active supported model 'openai/gpt-oss-20b' in '.env'.
  2. Added defensive reasoning tag stripping in 'src/llm_client.py':
     if "<think>" in content and "</think>" in content:
         content = content.split("</think>")[-1]

Verification Output:
  Model: openai/gpt-oss-20b
  Intent: delivery_delay (Conf: 0.95)
  Final Reply: We’re sorry to hear about the delay. Please send us a DM with your order number...
